Using the simulator

  1. Enter your assumptions: current portfolio, annual contribution and its growth rate, years to retirement and in retirement, expected return, volatility, inflation, first-year retirement spending, CPP/OAS/pension income, and the number of simulations (1–10,000). Load Sample Scenario fills in a random plausible example.
  2. Choose the target .xlsx workbook for the report (a new or existing file), and optionally tick Also export to CSV and choose a CSV path.
  3. Click Run Simulation. Invalid inputs are named in the status line. Spending must be greater than pension income, which is the same rule the web version applies.

The model (identical to the web version): returns are drawn from a normal distribution each year; contributions grow yearly until retirement; withdrawals start at spending minus pension income and rise with inflation; a path fails when it reaches $0 in retirement.

Outputs

  • Excel report in the workbook you chose, as three sheets that are replaced on each run (other sheets in the workbook are left alone): MC_Summary (inputs and headline results), MC_Percentiles (10th/25th/50th/75th/90th percentile for every year, with the retirement year marked) and MC_Chart (fan-chart image).
  • CSV (optional): columns Year, Date, P10, P25, P50, P75, P90.
  • Values are nominal dollars; the inflation rate used is recorded in the report. The web version can also show real (today's) dollars.

Troubleshooting

“Pension income must be less than annual retirement spending”

If guaranteed income covers all spending, there's nothing for the portfolio to fund, so the simulation isn't needed. Adjust either value.

The Excel report can't be saved

Close the workbook if it's open in Excel, and choose a folder you can write to (not a read-only or synced placeholder folder).

For developers

The folder follows a simple layout: scripts/ holds everything the program needs (main.py, the monte_carlo package, bootstrap.py, pinned requirements.txt), config.toml sets the supported Python range and entry point, and files/ holds tests and generated scratch data. Unit tests are included in the source repository (not the ZIP); run them with the project's Python after installing pytest:

.venv/bin/python -m pip install pytest
.venv/bin/python -m pytest files/tests -q

On Windows use .venv\Scripts\python.exe.
