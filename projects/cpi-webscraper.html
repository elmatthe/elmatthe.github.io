Overview

  • In your browser

    Five Statistics Canada CPI series with no key at all, and thirteen FRED series (US CPI, unemployment, fed funds, Treasury yields, the 10y–2y spread, PCE, the S&P 500) with your own free FRED key.

  • The same 19 columns

    The CSV has exactly the A–S columns of the model's CPI_Downloader sheet, in the same order, with the same headers, dates and blank cells as the desktop tool's CSV.

  • Straight into Excel (desktop)

    The Windows tool writes the same data into your existing .xlsx or .xlsm model through desktop Excel, keeping its formulas, formatting and history.

Why writing into the workbook stays on the desktop. Updating the existing model safely needs desktop Microsoft Excel for Windows: browser spreadsheet libraries neither recalculate this model's formulas nor keep its charts and dynamic arrays. The web app therefore gives you the data and a CSV; the desktop tool writes it into the workbook.

Web app

Runs in this page. Statistics Canada is contacted directly; FRED is reached through a small gateway, because FRED's API does not answer requests from other websites. Without a FRED key you get the Canadian columns and the US columns stay blank, with the reason shown.

    Data sources

    The web app and the desktop tool use the same columns, sources and rules, checked by automated tests against each other (their CSV files are byte-identical for the same data). Monthly rows are keyed to the first day of each month from January 1913. History before a series begins stays blank: nothing is interpolated, forward-filled, or replaced by a proxy series. Daily FRED series (DFF, SP500, T10Y2Y) use the last valid observation of each month; for the current, unfinished month these three columns are left blank until the month ends, so a mid-month value is never written as a month-end value.

    Where the web app gets the data: Statistics Canada's Web Data Service answers requests from any website, so your browser fetches the five Canadian series directly, with no key, in requests of up to 120 months. FRED's API does not answer requests from other websites, so the thirteen US series go through a small data gateway run for this site on Cloudflare's free tier: it accepts only these thirteen series and valid dates, forwards your own key to FRED, and stores nothing. Each source's status, request count and retrieval time is shown with the results.

    The web CSV has exactly these nineteen columns and headers in this order (A–S), every requested month, YYYY-MM-DD dates and empty cells for unavailable values; notes and attributions stay on the page so the layout stays identical to the model's raw sheet. “Core” here is Statistics Canada's all-items CPI excluding food and energy (tables 18-10-0004 and 18-10-0006), not the Bank of Canada's preferred core measures (CPI-trim, CPI-median). Statistics Canada revises the previous month's seasonally adjusted values every month and the last three years each January, and FRED series such as PCE are revised too; every download fetches the current published values, so re-running a range picks up revisions.

    S&P 500 history

    FRED publishes only about ten years of S&P 500 history, and S&P Dow Jones Indices restricts its reproduction. The bundled CPI.xlsx therefore contains no S&P 500 values (and no saved results derived from them), and neither this site nor its data gateway stores or caches any: column N is filled only when you fetch with your own FRED key, for your own use, in the web app or the desktop tool. Before keeping or sharing a file that contains it, confirm that your use is permitted. Because downloads now merge into the sheet, months you downloaded earlier are kept even after they leave FRED's window. The earlier optional Yahoo Finance backfill is no longer available.

    Workbook safety

    • Writes through a private Excel instance and changes contents only inside the owned A:S area of the target sheet. It never inserts or deletes rows, recreates sheets, or changes formulas, formats, named ranges, charts or tables.
    • Downloads are merged: the months you download replace those months in the sheet, and every other month already there is kept, so a single-month update no longer clears the history. Tick Replace all rows (with a confirmation) to make the sheet hold exactly the downloaded months.
    • Macros, events and external-link updates are disabled during the write. Worksheet calculation is suppressed so dynamic-array spills can't change model cells, and the workbook's own calculation mode is preserved. The model sheets are therefore not recalculated by the tool: after a download, open the workbook in Excel, press Ctrl+Alt+F9 and save. Whether Excel recalculates by itself on opening has not been verified.
    • The month range is limited to January 1913 through the current month. Downloads run in the background with progress and a Cancel button; nothing is written until every source has been fetched and checked.
    • .xlsm workbooks are opened with macros disabled and saved in the same format; workbooks with VBA have not been part of the automated tests.
    • Read-only, locked or protected targets, formulas or merged cells inside the raw area, and a missing sheet all fail with a clear message before any change is made.
    • The optional CSV uses the same columns and data with YYYY-MM-DD dates. A CSV failure is reported separately from an Excel write that already completed.

    Credentials & privacy

    • Your own free FRED API key is needed for the US columns (request one here: create an account at fred.stlouisfed.org, then My Account → API Keys). There is no shared or owner key: FRED's terms ask every user of an application to use their own. The Canadian columns need no key at all.
    • Web app: the key stays in this page's memory, or in this tab's session storage (cleared when you close the tab) if you tick Keep for this browser tab; it is never saved permanently. It is sent only over HTTPS, inside the body of each request, to the data gateway, which passes it to FRED in the form FRED requires and never logs, stores or returns it. It never appears in a web address, in the CSV, or in a message. Remove key forgets it. Scripts on this website could read session storage, so use a key you can replace (FRED lets you revoke and re-issue keys).
    • Web app requests: only series identifiers and dates go to Statistics Canada; series identifiers, dates and your key go to the data gateway and from there to FRED. No cookies are sent or set, and the gateway keeps no copy of any answer, so one visitor's data is never served to another.
    • Desktop tool: the key is saved, as plain text in config.toml inside your copy of the tool, only if you tick Remember on this computer. Never share that file. The download contains no API key or other credential; the bundled template's key field is blank, and the bundled workbook has no author names, local paths or add-in references.
    • During a desktop download only series identifiers, dates and your FRED key (to FRED) are sent, to Statistics Canada and FRED. Setup and repair also contact the Python package index (PyPI) and, if you agree to install Python, winget. Your workbook stays on your PC.

    Troubleshooting

    Web app: the US columns are blank

    Each blank cell says why. No FRED key: enter your key and fetch again. No gateway yet: this site's data gateway has not been set up, so the browser cannot reach FRED; the desktop tool can. Gateway unavailable or Key rejected: check the key at fred.stlouisfed.org and try again later. The Canadian columns are kept in every case.

    Web app: “Unavailable” or HTTP 409 from Statistics Canada

    Statistics Canada locks its tables during its daily update, usually between midnight and 08:30 Eastern time. The page tries three times, then marks only those months unavailable. Fetch again after 08:30 ET.

    Web app: the latest months are blank

    Not published means the source has not released that month yet (Canadian CPI for a month is published in the middle of the next month). Month not over appears in the end-of-month columns for the current month, by design.

    “The workbook is open” or the write fails

    Close the workbook in Excel, make sure the CPI_Downloader sheet exists and is unprotected, and try again on a copy. Excel must be the desktop Windows version.

    A source failed and nothing was written

    That's deliberate: data is written only when every source succeeded. Check your internet connection and FRED key, then retry. The error names the failing source.

    Setup stops before the program opens

    Read the message: it names the failing step (Python, dependencies, or config.toml). An invalid config.toml is kept as-is and blocks downloads until fixed; compare it with scripts/config-default.toml. The guide covers each case.
